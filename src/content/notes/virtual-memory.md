虚拟内存常被误解成「内存不够时拿硬盘顶一下」。它其实是现代操作系统的基石，身兼三职：

## 它到底在忙什么

1. **扩建地址空间**：给每个进程一个连续、独立的虚拟地址空间，让程序以为自己独享一大块内存。实际是物理内存 + 磁盘页面文件拼出来的「障眼法」。
2. **隔离与保护**：进程之间地址空间相互隔离，一个程序崩溃不会踩烂别的程序；内核区域也靠这层机制保护。
3. **换页调度**：不常用的内存页换出到磁盘，把快速物理内存留给活跃数据，需要时再换入。

```text
应用进程 ──访问──> 虚拟地址空间
                   ├─ 物理内存（快，容量有限）
                   └─ 页面文件（慢，容量大）  ← 换入/换出
```

## 32 GB 的机器还要分配吗

**要，但别关掉，也不用调很大。** 让系统自动管理即可。

- 32 GB 日常几乎不会真的换页，页面文件是「沉睡的保险丝」，性能影响可忽略。
- 但 Windows 的提交内存机制、Adobe 全家桶、虚拟机、部分游戏反作弊、数据库软件都会**预留**大量地址空间；蓝屏转储也依赖页面文件。关掉它，某些软件会报「内存不足」，明明你还剩 20 GB。

一句话：**页面文件就像消防栓——平时一滴水不用，真没那天才知道它多重要。**

## 延伸

内存映射文件、共享库、写时复制（COW）这些高级玩法，底层全靠虚拟内存机制支撑。理解它，再看 JVM 内存模型、Redis 内存管理都会通透很多。
